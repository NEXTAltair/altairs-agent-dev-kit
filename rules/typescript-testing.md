# TypeScript / JavaScript Testing Rules

TypeScript / JavaScript のテスト方針。テストの書き方そのものではなく、lint やモデルの既定挙動では決まらない
判断だけを持つ。設定例は vitest 5.1.0 で動作を確認した (2026-11-12)。

> **プロジェクト固有:** テストランナー (vitest / `node:test` 等)、カバレッジの数値目標、CI で実行する
> コマンドとフィルタは導入先で追記する。

## 実行

- テストは 1 回で終わるコマンドで実行する。vitest は `vitest run` と書く (素の `vitest` は対話端末では
  ファイル監視に入り、終了しない)。
- テストも型チェックの対象にする (`tsconfig.json` の `include`)。型が合わないテストは実物とずれている。
- `test.only` / `describe.only` を commit しない。残ると他のテストが実行されないまま CI が通る。
  Biome の `noFocusedTests` が検出する。`test.skip` は理由と解除条件をコメントに書く。

## 決定論的なテストと実環境の検証を分ける

- CI で走るテストは、時刻・乱数・ネットワーク・外部プロセスに依存させない。時刻は fake timer、外部との通信は
  引数で渡した実装の差し替えで固定する。
- 実 API・実ブラウザ・実デバイスを使う検証は、ファイル名 (`*.live.test.ts` 等) と実行コマンドを分け、
  既定の `test` では走らせない。走らせたかどうかを成果の報告に書く。

## モック

- モジュールごと差し替える (`vi.mock`) より、依存を引数で受け取る形にして差し替える。モジュールの mock は
  import の構造が変わると黙って効かなくなる。
- mock の戻り値に実物と同じ型を付ける (`satisfies`)。型が外れた mock は、実物が変わってもテストが通り続ける。
- 自分が書いたコードを mock しない。mock するのは境界 (ネットワーク、時刻、ファイルシステム、外部プロセス) だけ。

## カバレッジ

- 閾値を置くなら設定ファイル (`coverage.thresholds`) に書き、下げて通さない。
- 対象から外すのは生成コードと型定義だけ。テストが書きにくいという理由で外さない。

## 変更したら

- 変更したコードを通るテストを実行してから commit する。型チェックと lint だけでは動作を確かめたことにならない。
- 不具合の修正には、修正前に落ちて修正後に通るテストを付ける。
